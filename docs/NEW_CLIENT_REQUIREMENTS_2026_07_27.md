# متطلّبات العميل الجديد — خطّة التنفيذ

**التاريخ:** 2026-07-27
**الأنظمة المطلوب الربط معها:** إسكادينيا (Escadenia) • بنتا (Penta)
**الحالة:** خطّة معتمدة — قيد التنفيذ

---

## الخلاصة التنفيذيّة

معظم متطلّبات العميل **متوفّرة وشغّالة على الإنتاج**. الفجوات الحقيقيّة محصورة في
**طبقة الـ Public API** (خدمة OTP + إرسال القوالب والمستندات عبر API)، وهي شغل
مستقلّ لا يعتمد على أيّ جهة خارجيّة.

الجزء الوحيد **المشروط بجهة خارجيّة** هو سحب الفواتير من إسكادينيا وبنتا — لأنّه
يتطلّب تعاون مورّدي هذين النظامين، وهذا خارج سيطرتنا.

| | |
|---|---|
| **الأساس المستقلّ (P0)** | ~4 أيّام عمل — نلتزم بها |
| **كونكتورات سحب الفواتير (P2)** | 5-8 أيّام لكل نظام — **مشروطة** بوصول ووثائق من المورّد |

## 1. جرد المتطلّبات مقابل الواقع

### ✅ متوفّر وشغّال — لا يحتاج عمل

| المتطلّب في العقد | التغطية الحاليّة |
|---|---|
| توفير WhatsApp Business Platform | 360dialog Partner (LIVE منذ 2026-06-11) — تزويد أرقام جديدة من داخل النظام |
| منصّة إدارة الحملات | كاملة: جدولة، شرائح ذكيّة، سقف تكرار، نافذة إرسال، تحليلات، تصدير Excel |
| الرسائل الخدمية (Utility) | قوالب utility تُنشأ وتُعتمد وتُرسل من المحادثات والحملات |
| التقارير التشغيلية | Dashboard + Analytics + تصدير Excel + لوحة الجودة والـ tier |
| متابعة الأداء | مؤشّرات Meta pacing، messaging tier، معدّلات التسليم والقراءة، تنبيهات صحّة عبر المستأجرين |
| الدعم الفنّي | نظام تذاكر داخل المنصّة + Flare (backend) + Sentry (frontend) |
| واجهات التكامل — Webhooks | موزّع أحداث حقيقي مع توقيع: `message.received` / `message.sent` |
| مفاتيح API | `sk_live_corbit_*` + حصّة شهريّة لكل باقة + إدارة من الإعدادات |
| تدريب المستخدمين | Help Center داخل المنصّة + أدلّة PDF |
| إرسال ملفّات PDF (الشهادات) | `WhatsAppService::sendMedia()` يدعم `document` + اسم ملف صحيح |
| قوالب برأس مستند | `header_format: document` مبني ومختبَر + مهمّة إعادة محاولة للرفع |
| روابط آمنة للملفّات | نمط `temporaryUrl` موقّع على bucket خاص (مستخدم في المرفقات والتحويلات البنكيّة) |

### ⚠️ ناقص — يحتاج تنفيذ

| الفجوة | الأثر على العميل |
|---|---|
| لا توجد خدمة OTP للطرف الأوّل | متطلّب صريح في العقد — غير قابل للتسليم بدونه |
| الـ Public API يرسل **نصّاً فقط** | أي رسالة خدمية خارج نافذة 24 ساعة **سترفضها Meta** |
| لا يوجد إرسال مستندات عبر API | الشهادات لا يمكن إرسالها آليّاً من نظام العميل |
| لا يوجد استعلام عن حالة الرسالة | العميل لا يقدر يعرف هل وصلت الرسالة أم لا |
| لا يوجد توثيق API للعملاء | فريق التكامل عندهم لا يقدر يبدأ |
| لا يوجد كونكتور لإسكادينيا/بنتا | سحب الفواتير غير ممكن |

## 2. خطّة العمل مرتّبة حسب الأولويّة

### 🔴 P0 — الأساس المستقلّ (~4 أيّام) — نبدأ فوراً

> كلّ ما في هذا القسم **لا يعتمد على أيّ جهة خارجيّة**. يُنجَز بالكامل بغضّ النظر
> عن موقف مورّدي إسكادينيا وبنتا.

#### P0-1 — توسيع الـ Public API: قوالب + مستندات + حالة الرسالة
**التقدير:** 1 يوم

الوضع الحالي — [`routes/api.php:723-729`](../../corbit-backend/routes/api.php) يكشف 3 نقاط فقط،
و[`PublicApiController::sendMessage()`](../../corbit-backend/app/Http/Controllers/Api/V1/PublicApiController.php)
يقبل `text` فقط ويثبّت `message_type = 'text'`.

المطلوب:
- [ ] `POST /v1/messages` يقبل `type: text | template | document`
- [ ] دعم `template_name` + `language` + `parameters[]` (يستدعي `WhatsAppService::sendTemplate()`)
- [ ] دعم `document_url` + `filename` + `caption` (يستدعي `WhatsAppService::sendMedia()`)
- [ ] `GET /v1/messages/{id}` — حالة التسليم (`sent` / `delivered` / `read` / `failed`)
- [ ] `GET /v1/templates` — قائمة القوالب المعتمدة ليختار منها نظام العميل
- [ ] الحفاظ على كلّ البوّابات الحاليّة: حدود الباقة، سياسة الإرسال، عدّاد الاستهلاك

**معيار القبول:** استدعاء API واحد يرسل قالب utility لرقم خارج نافذة 24 ساعة ويصل فعليّاً.

---

#### P0-2 — خدمة OTP للطرف الأوّل
**التقدير:** 2 يوم

> ⚠️ `OtpService` الحالي **ليس** المطلوب — هو تحقّق دخول موظّفينا عبر SMS
> ([`OtpService.php`](../../corbit-backend/app/Services/OtpService.php))، ومربوط بـ `User`
> ولا يمرّ بواتساب. خدمة العميل تُبنى منفصلة.

المطلوب:
- [ ] جدول `otp_requests` — مرتبط بـ `org_id` (وليس `user_id`)، الرمز **مُجزّأ** (hashed) لا نصّاً صريحاً
- [ ] `POST /v1/otp/send` — توليد + إرسال عبر قالب `authentication`
- [ ] `POST /v1/otp/verify` — تحقّق + تعليم الرمز مستخدَماً (منع إعادة الاستخدام)
- [ ] صلاحيّة قابلة للضبط (افتراضي 5 دقائق) + فترة تهدئة بين الطلبات
- [ ] سقف محاولات فاشلة قبل الإبطال (منع التخمين)
- [ ] حدّ معدّل لكلّ رقم ولكلّ منظّمة (منع إساءة الاستخدام والاستنزاف)
- [ ] احتساب التكلفة على محفظة المنظّمة (بعكس OTP الداخلي المجّاني)
- [ ] الرمز **لا يُسجَّل أبداً** في الـ logs

**معيار القبول:** دورة كاملة send → استلام على واتساب → verify ناجح، ثم verify ثانٍ بنفس الرمز يفشل.

---

#### P0-3 — خدمة تسليم المستندات الآمن (الشهادات والفواتير)
**التقدير:** 0.5 يوم

> Meta تجلب الملف من الرابط بنفسها ([`sendMedia():291`](../../corbit-backend/app/Services/WhatsAppService.php)
> يمرّر `['link' => $url]`) — فالرابط لازم يكون قابلاً للوصول من الخارج.
> **الشهادات مستندات شخصيّة** فلا يجوز وضعها على رابط دائم مكشوف.

النمط الآمن موجود أصلاً ([`ConversationController:510-518`](../../corbit-backend/app/Http/Controllers/Api/ConversationController.php)) — المطلوب استخلاصه وتشديده:
- [ ] خدمة `SecureDocumentDelivery` مركزيّة تعيد رابطاً موقّعاً قصير العمر
- [ ] صلاحيّة قصيرة (~15 دقيقة) — كافية لجلب Meta مع إعادة المحاولة، وتنتهي سريعاً
- [ ] حذف تلقائي للملفّات المنتهية (مهمّة مجدولة)
- [ ] تسجيل تدقيقي: أيّ مستند أُرسل لأيّ رقم ومتى

**معيار القبول:** الرابط يشتغل مع Meta، ويعطي 403 بعد انتهاء المدّة.

### 🟡 P1 — تعزيزات مطلوبة قبل التشغيل الفعلي (~1.5 يوم)

- [ ] **توسيع أحداث الـ webhook** — إضافة `message.delivered` / `message.read` / `message.failed`
      حتى يقدر نظام العميل يتابع دورة حياة الرسالة (حاليّاً `received` و `sent` فقط)
- [ ] **رفع المستندات عبر API** — نقطة `POST /v1/media` ترفع الملف وتعيد معرّفاً،
      لأنّ نظام العميل قد لا يقدر يستضيف الشهادات على رابط عام
- [ ] **سجلّ استدعاءات API** لكل منظّمة — ضروري لتشخيص الأعطال مع فريق العميل
      (متطلّب «معالجة الأعطال» في العقد)

### 🟢 P2 — كونكتورات سحب الفواتير — **مشروطة بجهة خارجيّة** ⛔

> **لا نلتزم بتاريخ تسليم لهذا القسم قبل استلام الوصول والوثائق.**
> عدّ الأيّام يبدأ من تاريخ توفّرها، لا من تاريخ توقيع العقد.

**غير موجود في الكود إطلاقاً** — تكاملاتنا الحاليّة (سلّة، زد، شوبيفاي) كلّها منصّات
سحابيّة بـ OAuth جاهز، ونمطها **لا ينطبق** على أنظمة مثبّتة داخل شبكة العميل.

المتطلّبات المسبقة قبل كتابة أيّ سطر كود:
- [ ] تحديد نوع النشر: سحابي أم داخل شبكة العميل (on-premise)
- [ ] وثائق API رسميّة من المورّد — **مستند مكتوب، لا وعد شفهي**
- [ ] بيانات وصول للاختبار (بيئة تجريبيّة مفضّلة)
- [ ] وصول شبكي: VPN أو إدراج عناوين IP في القائمة البيضاء
- [ ] **تأكيد خطّي من المورّد بالموافقة على التكامل** ← هذا هو العائق الحقيقي عادةً
- [ ] الاتّفاق على الحقول المطلوبة بالضبط (نأخذ الحدّ الأدنى: رقم الفاتورة، المبلغ، الجوّال، الحالة)

**التقدير بعد اكتمال ما سبق:** 5-8 أيّام لكل نظام.

## 3. الاعتماديّات الخارجيّة والمخاطر

| المخاطرة | الأثر | التخفيف |
|---|---|---|
| مورّد إسكادينيا/بنتا يرفض التكامل أو يطلب رسوماً | P2 يتوقّف كلّيّاً | بند عقدي صريح + فصل المرحلتين |
| اعتماد قوالب Meta | 1-3 أيّام لكل قالب، والصياغة التسويقيّة تُرفض | تجهيز القوالب وتقديمها **مبكّراً**، بصياغة خدميّة بحتة |
| الوصول الشبكي داخل شبكة العميل | يعطّل P2 | طلبه من اليوم الأوّل |
| بيانات شخصيّة وماليّة في الرسائل | مخاطرة أمنيّة | تقليل الحقول للحدّ الأدنى + روابط موقّعة قصيرة العمر + سجلّ تدقيقي |

## 4. التقسيم المقترح في العقد

**المرحلة الأولى — ملتزمون بها (~5.5 يوم عمل):**
المنصّة + الحملات + OTP + إرسال الشهادات + API موثّق.
العميل يقدر يشغّل فوراً حتى لو كان إدخال الفواتير يدويّاً أو عبر ملف في البداية.

**المرحلة الثانية — مشروطة:**
سحب الفواتير الآلي. **تبدأ مدّتها من تاريخ استلام الوصول والوثائق من المورّد.**

**صياغة مقترحة للعقد:**
> «تلتزم كوربت بتوفير واجهات API موثّقة ودعم فنّي لفريق التكامل لدى الطرف الأوّل.
> ويقع على الطرف الأوّل تأمين تعاون مورّدي أنظمته (إسكادينيا/بنتا) وتوفير الوصول
> والوثائق اللازمة، وأيّ رسوم تكامل تفرضها تلك الجهات.»

بدون هذا الفصل، أيّ تأخير من المورّدين يُحتسب تأخيراً علينا.

## 5. أسئلة معلّقة للعميل

1. هل يتوفّر حاليّاً وصول API لأنظمة إسكادينيا وبنتا، أم يحتاج طلبه من المورّد؟
   **(الإجابة تحدّد إن كانت المرحلة الثانية أسبوعاً أم ثلاثة أشهر)**
2. الشهادات — يولّدها نظامهم كـ PDF جاهز، أم نولّدها نحن من بيانات خام؟
3. الأحداث المطلوبة بالضبط؟ (كل حدث = قالب Meta منفصل يحتاج اعتماداً)
4. الحجم الشهري المتوقّع للرسائل؟ (يحدّد الـ tier والتسعير)
5. هل الشهادات تحتوي بيانات حسّاسة تستوجب ضوابط إضافيّة؟
